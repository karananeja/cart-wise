# Technical Design — F-018 Site footer with newsletter and help pages

- **Data:** `newsletter_subscribers` (email PK, normalised; `token_hash` unique, SHA-256 of a 32-byte random token; `source` `footer`; `created_at`; `unsubscribed_at`). Added to `schema.sql` with `CREATE TABLE IF NOT EXISTS`, which runs on every open, so existing databases get the table without a `SCHEMA_VERSION` bump (the spec's "schema version bump" is not needed for an additive table).
- **API** (`apps/api/src/newsletter/`):
  - `POST /api/newsletter {email}` → `200 {ok:true}` for new and already-subscribed addresses. `400 INVALID_EMAIL` with `details.fields.email`. `429 TOO_MANY_REQUESTS` after 10 valid sign-ups per IP per hour (in memory, injectable clock, like the sign-in limiter).
  - New or returning (previously unsubscribed) addresses get a fresh token; an active subscriber is left alone (no second email).
  - `GET /api/newsletter/unsubscribe?token=` → `{maskedEmail}` (shared `maskEmail`); `POST /api/newsletter/unsubscribe {token}` → `200`. Unknown, used, missing or oversized tokens → `404 NOT_FOUND`. Only the POST unsubscribes.
- **Welcome email** (`apps/api/src/mail/newsletterEmail.ts`): sent through the F-016 `Mailer` when configured, after the response. A failure is logged with the SMTP error code only; the subscription stands. The link is `${WEB_BASE_URL}/newsletter/unsubscribe?token=…` (`WEB_BASE_URL` env or `AppOptions.webBaseUrl`, default `http://localhost:5173`; documented in `.env.example`).
- **Shared:** `newsletter_subscribed` analytics event; `NewsletterUnsubscribeLookup` type; `DELIVERY_RULES` (per-option prices) now exported from `checkout.ts`; `ZONE_AREAS` (zone areas in words) beside the pincode prefixes in `serviceability.ts`.
- **Web:**
  - `app/Footer.tsx`: Brand (name, tagline, decorative social glyphs and app badges in `role=group` captioned "… · coming soon", no links or buttons), Shop (top 6 categories by `productCount` from the cached `useCategories()`, then All products; only All products while loading or on error), Your account, Help, Newsletter; bottom bar with the demo notice, `© {year} Cartwise demo` and a "Store simulation (demo operator)" link to `/sim`.
  - Link columns use `useMediaQuery('(min-width: 640px)')` (`lib/useMediaQuery.ts`): a headed `nav` per column from `sm`, a native `<details>/<summary>` below it (one DOM, no duplicated links). Brand and Newsletter stay visible on phones.
  - `features/newsletter/`: `NewsletterForm` (client check with `normalizeEmail`, spinner, success replaces the form, one polite `role=status` for success/rate-limit/network messages, inline field error), `UnsubscribePage` (skeleton → "Unsubscribe k••••@…?" + button → confirmation; invalid/no token → "This link isn't valid anymore.").
  - `features/help/`: `HelpLayout` (title, intro, topic nav) and `HelpPages.tsx` (Delivery, Returns & refunds, Payments & EMI). Every number is computed from shared constants (`DELIVERY_RULES`, `FREE_DELIVERY_THRESHOLD_PAISE`, `ZONE_DAYS`, `ZONE_AREAS`, `PAYMENT_HOLD_MS`, `DELIVERY_CODE_ATTEMPTS`, `CANCELLABLE_STATUSES`/`ORDER_STATUS_LABELS`, `RETURN_WINDOW_MS`, `OFFERS`, `EMI_*`, `NO_COST_*`, `UPI_REQUEST_MS`).
  - Routes `/help/delivery`, `/help/returns`, `/help/payments`, `/newsletter/unsubscribe` are lazy.
