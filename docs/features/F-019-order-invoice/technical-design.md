# Technical Design — F-019 Order invoice (PDF)

- **Rules (shared):** `packages/shared/src/gst.ts` holds the FR-5 table (`GST_RATES`, by category slug), the ₹2,500 apparel/footwear threshold (`gstRate`; above it 18%), delivery at 18%, a default of 18% for unknown categories, the FR-6 inclusive split (`splitInclusive`, integer paise, CGST floored, SGST takes the odd paisa), `SELLER` (Karnataka; GSTIN "DEMO — not registered"), `invoiceNumber` and the Indian amount in words (lakh/crore).
- **Categories:** order lines don't store a category. At invoice time `OrderService.categoriesOf` looks it up by `product_id` (catalog ids survive reseeds), falling back to the slug; a missing product gets the default rate. No schema change.
- **Invoice data:** `apps/api/src/orders/invoice.ts` `buildInvoice(order, categories)` is a pure function returning everything the PDF draws: header, seller, bill-to from the address snapshot, item lines plus a delivery line when charged, totals (taxable, CGST/SGST or IGST, total tax), amount in words, payment summary (label, EMI plan, bank offer / No Cost EMI / Razorpay offer discount, amount paid, the discount note), the "Cancelled — refunded" banner and the refunds list. Lines and totals are always the original sale.
- **PDF:** `apps/api/src/orders/invoicePdf.ts` lays it out with `pdfkit` (MIT) on A4. Noto Sans Regular/Bold are vendored in `apps/api/assets/fonts/` (SIL OFL 1.1, `OFL.txt`) for ₹. Buffered pages give every page a running header (title, invoice number, demo note) and a footer (demo note, page x of y); long item and refund tables continue with their header repeated. Wide amounts shrink to fit their column.
- **Route:** `GET /api/orders/:id/invoice.pdf`: 401 signed out, 404 not the owner's (same lookup as the order API), 409 `INVOICE_NOT_AVAILABLE` until paid; otherwise `application/pdf`, `attachment; filename="Cartwise-Invoice-<id>.pdf"`, `Cache-Control: private, no-store`.
- **Web:** `features/orders/DownloadInvoiceButton.tsx` fetches the PDF, saves it through an object URL with the file name, shows a spinner while downloading and "Couldn't download the invoice. Please try again." on failure, and is disabled offline. Shown in the order page header and in the confirmation page's Payment card; both pages only render for paid orders (unpaid ones redirect to the payment page).
